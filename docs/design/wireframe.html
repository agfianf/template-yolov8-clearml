Model card

Three confidence thresholds coexist in this task and they are not alternatives. mAP and every curve are computed at the NMS floor, 0.001 — anything below it never reaches the metrics at all. The confusion matrix and every gallery are drawn at the display threshold, 0.25, because a matrix at the floor is all background. The threshold you would deploy at is the F1-optimal one, which for this run is 0.000.

Where the boxes sit in the frame, not how many there are: a model only learns the corners it is shown, and this one is shown the middle.

Image files

Everything above reads the label files. This block reads the images themselves — header only, .size, .mode and .format, with no pixel decode — so it is cheap enough to cover all 618 images rather than a sample. Six sizes account for 616 of them; what happens to those pixels on the way into the model is the rest of this block.

Orientation is the same fact viewed sideways: four fifths of the set is landscape, a fifth portrait, and a handful square.

Pixel count matters more than either, because it is what survives the resize. At imgsz 640 a 12 MP frame is thrown away at a ratio of about 30 to 1 in area, and every small object goes with it.

Operating threshold

τ* is the F1-optimal threshold, and it is none of the other three confidences in this task. Here F1 is highest at the very floor and falls monotonically from there: raising the threshold discards recall without buying precision, which is the signature of scores that do not rank. Read it next to recall — this curve is computed over predictions only, so it is blind to false negatives.

Size and shape

Where the misses actually are. Object sizes use this dataset's own terciles at 38px and 51px at imgsz 640, not COCO's 32/96 absolutes. Density matters more than size here: the median image carries about twenty fruitlets and the tail runs past a hundred and forty, well beyond the default max_det headroom once recall improves.
